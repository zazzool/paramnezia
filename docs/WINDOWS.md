# Paramnezia для Windows

Тот же клиент, что на Android: те же экраны, ключи `vpn://`, приглашения, семейная группа, манифесты и серверы.
Windows 10 и 11, x64. Установщик `Paramnezia-Setup-<версия>.exe` лежит в каждом
[релизе](https://github.com/zazzool/paramnezia/releases/latest) рядом с APK.

## Как устроено

```
desktop/                    Windows-приложение (Kotlin, Compose Desktop, свой Java-рантайм внутри)
  build.gradle.kts          берёт экраны из app/src/main/kotlin/.../ui без изменений (задача syncSharedUi)
  src/.../desktop/          Windows-слой: служба, DPAPI, трей, автозапуск, файлы, скриншоты
  installer/paramnezia.iss  установщик (Inno Setup)
client/                     общий код Android и Windows: состояние, импорт, семейная группа (fleet), ссылки, «как вас видят сайты»
tunnel/src/main/go/
  dnsfilter/                DNS-фильтр (общий с Android)
  windows/                  служба paramnezia-service.exe: amneziawg-go v3 на Wintun
  windows/firewall/         защита от утечек DNS (WFP, из wireguard-windows)
```

**Два процесса.** Приложение работает без прав администратора. Туннель держит служба `ParamneziaTunnel`
(«Paramnezia VPN»), которую установщик регистрирует один раз. Сама служба туннель не поднимает: только по
запросу приложения через локальный канал `\\.\pipe\paramnezia` (подключаться могут SYSTEM, администраторы и
вошедший пользователь, из сети нельзя). Запрос и ответ — по одному JSON на соединение: `version`, `up`, `down`,
`status`, `set` (keepalive), `rules` (DNS-фильтр), `direct`.

**Маршруты.** Как на Android: в туннель идёт всё, кроме российских сетей и локальной сети, но Windows не умеет
исключать маршруты, поэтому приложение передаёт дополнение (`RoutePlanner`, бюджет 8000 маршрутов). Адрес
сервера и прямые DNS-серверы из туннеля исключены. Если в конфиге нет IPv6, зарубежный IPv6 уходит в туннель
и там пропадает (иначе он шёл бы мимо VPN).

**DNS.** Windows спрашивает только виртуальный резолвер 198.18.0.53 в туннеле; фильтр отвечает сам (реклама),
российские имена спрашивает напрямую, остальные через сервер. Фильтр WFP запрещает DNS (порт 53) всем, кроме
службы и адаптера Paramnezia, поэтому провайдер не видит и не подменяет имена.

**Мимо туннеля.** Проверки «Российские сайты» и установка серверов по SSH идут через SOCKS5-прокси службы на
127.0.0.1 (случайный логин и пароль), его соединения привязаны к физическому интерфейсу.

**Программы мимо VPN.** В Windows нет маршрутов «для программы», а драйвер ядра (как у Mullvad, Proton,
NordVPN) без сертификата подписи не загрузится. Поэтому решает служба: для первого пакета каждого TCP- и
UDP-соединения она смотрит в таблицах соединений Windows (`GetExtendedTcpTable`/`GetExtendedUdpTable`), какая
программа его открыла. Соединения программ из списка не идут на сервер: им отвечает стек gVisor внутри службы, а
настоящее соединение служба открывает через физический интерфейс (`IP_UNICAST_IF`). Код: `tunnel/src/main/go/splitapp`
и `windows/split.go`. Список — имена файлов (`Telegram.exe`) в том же `forceDirect`, что и приложения Android.
Ограничения: DNS и ping таких программ идут через VPN, входящие соединения с домашнего адреса не принимаются,
уже открытые соединения не переключаются (перезапустите программу).

**Сторож.** Раз в минуту приложение смотрит рукопожатие и проверяет DNS через туннель; после двух неудач
переподключается и переходит на резервный сервер семьи, как на Android.

**Хранилище.** `%LOCALAPPDATA%\Paramnezia`: состояние шифруется AES-GCM, ключ защищён DPAPI (только этот
пользователь на этом компьютере). Журнал службы: `%ProgramData%\Paramnezia\service.log`.

**Чем отличается от Android.** Нет виджета и плитки; вместо них трей. Вставка QR — из буфера обмена (снимок экрана) или из файла с картинкой.
Закрытое окно сворачивается в трей, VPN продолжает работать. Автозапуск при входе — по желанию, в настройках.

## Defender и SmartScreen

Те же правила, что [для Play Protect](PLAY-PROTECT.md), по смыслу:

- приложение ничего не скачивает и не запускает само: о новой версии оно только сообщает, установщик скачивает
  браузер по кнопке «Скачать», запускает пользователь (подписанный `release-windows.json`, пакет
  `net.paramnezia.windows`);
- нет удалённых команд, скрытых процессов, внедрения в другие программы; служба делает только туннель и
  отвечает только локальному приложению;
- автозапуск выключен, пока пользователь его не включит; удаление убирает службу, адаптер и автозапуск;
- драйвер Wintun — официальная подписанная сборка (контрольная сумма закреплена в `windows-build.ps1`).

Сертификат подписи кода не используется (решение владельца проекта): установщик и программа не подписаны.
Поэтому при первом запуске установщика SmartScreen показывает синее окно «Система Windows защитила ваш
компьютер». Это не находка антивируса, а «программа неизвестного издателя»:

1. Нажмите **«Подробнее»** (ссылка под текстом).
2. Появится кнопка **«Выполнить в любом случае»** — нажмите её.
3. Windows спросит разрешение на изменения (служба туннеля ставится с правами администратора) — «Да».

Если браузер (Edge) пишет, что файл «обычно не скачивают»: «…» → «Сохранить» → «Показать больше» →
«Всё равно сохранить». Подлинность файла можно проверить по SHA-256 из подписанного `release-windows.json`.

## Сборка

```sh
./gradlew -Pparamnezia.jvmOnly=true :desktop:run           # запустить (на Linux без службы: только интерфейс)
./gradlew -Pparamnezia.jvmOnly=true :desktop:screenshots   # экраны с демо-данными в desktop/build/screenshots
(cd tunnel/src/main/go && GOOS=windows CGO_ENABLED=0 go build -o paramnezia-service.exe ./windows)
```

Установщик собирается только на Windows: `.github/scripts/windows-build.ps1` (Go, Wintun, `createDistributable`,
Inno Setup). Служба для отладки: `paramnezia-service.exe debug` в консоли администратора.

CI (`build.yml`, задача «Windows installer») собирает установщик на `windows-latest` и прогоняет
`windows-service-check.ps1`: тихая установка, служба отвечает, туннель поднимает адаптер Wintun с адресом и
маршрутом, трафик уходит в amneziawg-go, прокси «напрямую» работает и не пускает с чужим паролем, туннель
снимается, удаление убирает службу. Установщик лежит в артефакте `paramnezia-windows`, экраны — в
`windows-screens`.

При выпуске (`release.yml`) установщик прикладывается к релизу, а `release-windows.json` подписывается тем же
ключом релизов, что и `release.json`.
