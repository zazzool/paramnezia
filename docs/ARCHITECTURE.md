# Архитектура

Подробно: [DEVELOPMENT.md](DEVELOPMENT.md) (как вести разработку), [PROTOCOLS.md](PROTOCOLS.md) (форматы и
протоколы), [SERVER.md](SERVER.md) (сервер), [RELEASE.md](RELEASE.md) (выпуск версий).

```
client/       Общий код Android и Windows: состояние, импорт, флот, ссылки, видимость адресов
app/          Android-приложение (Compose): экраны (общие с Windows), хранилище, OTA, синхронизация
desktop/      Windows-приложение: те же экраны, служба туннеля на Go (Wintun), установщик — WINDOWS.md
tunnel/       VpnService + нативная библиотека: amneziawg-go v3, JNI, DNS-фильтр (Go)
core/         Чистый Kotlin/JVM: конфиги, форматы AmneziaVPN, маршруты, флот, релизы
deploy/       Установка и управление сервером по SSH (скрипты в resources)
releasetool/  CLI для CI: ключ релизов и подпись release.json
tools/bypass-lists/  Генератор списков «российское напрямую» и списка трекеров
```

## Туннель

`ParamneziaVpnService` строит интерфейс по `TunnelSpec`, передаёт дескриптор в Go (`pnTurnOn`) и защищает
UDP-сокеты WireGuard от петли. Режим «экономии» реализован так:

- **Сторож живости без опроса сети.** Раз в минуту при включённом экране и раз в 15 минут при выключенном
  (через `Handler` главного потока, поэтому во сне он просто ждёт) читаются счётчики туннеля. Сеть
  используется, только если они подозрительны: рукопожатие старше 180 с или исходящий трафик без входящего.
  Тогда через туннель уходит один DNS-запрос к 1.1.1.1/8.8.8.8/9.9.9.9. Нет ответа: туннель пересоздаётся с
  новыми сокетами (лечит зависшие NAT-привязки), после двух неудач подряд берётся другой сервер флота.
  Дополнительные проверки: через 20 с после подключения, 15 с после смены сети, 3 с после включения экрана.
  Без рабочей физической сети ничего не трогается.
- **Keepalive** при выключенном экране меняется частичным UAPI-set, без переподключения.
- Go-рантайм пропатчен на `CLOCK_BOOTTIME`, чтобы таймеры WireGuard не сбивались в глубоком сне.
  `SetMemoryLimit` равен 48 МБ, UAPI-сокета нет.

## Маршруты и DNS

Android 13+ использует `excludeRoute`: весь трафик идёт в туннель, а российские блоки исключаются. На версиях
ниже маршруты строятся как дополнение: «всё, кроме российского». Бюджет 3000 маршрутов (лимит Binder). Списки
упорядочены по важности: сначала сети ключевых сервисов (ASN), затем крупные блоки. Поэтому сервисы из
`RoutingTest.keyRussianServicesGoDirect` проходят мимо туннеля на любом устройстве.

DNS приложений внутри VPN направлен на виртуальный адрес `198.18.0.53`. Его запросы перехватываются в Go,
прямо в `tun.Device.Read`:

| имя | ответ |
|---|---|
| в `blocklist.txt` (и не в `allow.txt`) | 0.0.0.0 / :: локально |
| в `domains.txt` (российское) | российский резолвер (по умолчанию 77.88.8.8) через защищённый сокет вне туннеля |
| остальное | DNS сервера туннеля, через туннель |

Ответы кэшируются по TTL (от 10 с до 10 мин, до 1024 записей), запросы мультиплексируются через один сокет на
маршрут. Ограничения: содержимое HTTPS (параметры URL, cookies) недоступно; приложения, целиком исключённые из
VPN, фильтра не видят (для них есть системный «Частный DNS»).

## Флот

`FleetManifest` хранит серверы (первый основной), устройства с постоянными адресами и зеркала. Каждая версия
подписывается Ed25519 и шифруется AES-256-GCM (AAD = fleetId:version). Устройство принимает только более новую
версию с верной подписью, поэтому старый манифест подсунуть нельзя.

Приглашение — это обычный ключ `vpn://` для основного сервера. AmneziaVPN его импортирует, а Paramnezia ещё и
вступает во флот по полю `paramnezia_fleet`.

В манифесте едет и `policy`: настройки администратора (обход российского, локальной сети, блокировка рекламы,
списки «через VPN» и «напрямую», российские DNS). Ведомое устройство применяет их при каждой новой версии;
режим батареи остаётся своим. Админ меняет настройку → через 3 с выходит новая версия (если что-то изменилось).
Выключается переключателем «Мои настройки на всех устройствах».

Обычный HTTP приложению разрешён только к `10.8.1.1` (сервер внутри туннеля, `res/xml/network_security_config.xml`);
до 2.2.0 этого файла не было, и Android 9+ молча запрещал чтение манифеста и `release.json` внутри туннеля.

Каналы манифеста (побеждает самая новая валидная версия):

1. `http://10.8.1.1:8080/fleet.json` внутри туннеля (busybox httpd в контейнере сервера);
2. резервный канал: секретный GitHub gist, `gist.githubusercontent.com/…/raw/fleet.json` и
   `api.github.com/gists/<id>` (два разных хоста). Админ вставляет один токен с правом `gist`, приложение само
   создаёт gist, вписывает оба адреса в манифест и обновляет gist при каждой новой версии. Если gist удалили,
   создаётся новый и устройства получают его адрес;
3. если не ответил никто, HTTPS-зеркала через Orbot (SOCKS `127.0.0.1:9050`), когда он установлен и запущен.
   Orbot исключён из нашего туннеля. Своего Tor-кода в приложении нет.

Когда устройство читает манифест: сразу после подключения и при переходе на другой сервер, раз в час пока туннель
работает (один маленький запрос внутрь туннеля, зеркала только если сервер не ответил), при открытии приложения
(не чаще раза в 15 минут), раз в 12 часов из WorkManager (все каналы) и сразу, когда сервер перестал отвечать.

Почему не P2P, блокчейн или встроенный Tor: [PLAY-PROTECT.md](PLAY-PROTECT.md#доставка-настроек-что-рассматривали).

Переключение работает так. Устройство с мёртвым сервером сначала синхронизируется (вдруг админ уже сменил
мастер), а затем выбирает первый не заблокированный сервер. Повторить попытку на заблокированном сервере оно
попробует через 6 часов. Если мастер недоступен для админа, админ-устройство само повышает резервный сервер.

## OTA

`Release`: пакет, versionCode, minSdk, SHA-256 и размер APK, сертификат подписи и URL. Подпись
Ed25519 ставится ключом релизов. Публичный ключ вшит в сборку (`BuildConfig.RELEASE_KEY`).

Приложение читает `https://github.com/zazzool/paramnezia/releases/latest/download/release.json` (и во флоте `release.json` внутри туннеля) при
запуске, не чаще раза в 12 часов, и по кнопке. «Скачать» открывает APK в браузере; ставит его Android, как при
первой установке. У приложения нет разрешения на установку пакетов. Почему так: [PLAY-PROTECT.md](PLAY-PROTECT.md).

## Одноразовые ссылки

APK один и тот же для всех: официальный релиз, байт в байт как его подписал apksigner. Страница на Android в два
шага: «Скачать Paramnezia» (первым — APK из GitHub Releases, запасным — копия на этом
сервере, которую сервер скачал и проверил сам) и «Открыть приглашение в Paramnezia» (intent-ссылка
`intent://…#Intent;scheme=vpn;package=net.paramnezia`, то есть открывается именно Paramnezia, а не другое
приложение с `vpn://`). Ключ на странице можно и скопировать. Сведения о версии для страницы (`app.json`) берутся
из подписанного релиза, который знает админ-устройство; своего APK приложение никуда не передаёт.

Без токена та же страница — публичная «страница для семьи»: значок, скриншоты (`invite/shot-*.webp`, из
эмулятора CI), кнопка скачивания последнего релиза (`app.json`, затем копия на сервере), шаги и вопросы. Она
ставится сама после развёртывания каждого сервера (`Servers.deploy`, `FleetManager.create/addServer` →
`Links.preparePage`, в том числе для серверов, купленных через API хостера) и отдаётся тем же контейнером
`paramnezia-invite`. Картинки передаются в `invite-server.sh` base64-строками (`PN_INVITE_ASSETS`).

Если Paramnezia уже установлена, страница на Android сразу (без нажатия) берёт приглашение и открывает его
intent-ссылкой; без приложения браузер возвращается на страницу с `?noapp` и показывает шаги установки.
Полученное приглашение страница хранит в `localStorage` браузера, поэтому установка может занять сколько угодно
времени (окно повторной выдачи на сервере всего 30 минут).

Файлы настроек (с 2.2.0): вместо ссылки админ может отправить каждому файл `<имя>.vpn` (внутри ключ `vpn://`, для
флота с частью `paramnezia_fleet`) через системное меню «Поделиться» (`ui/Share.kt`, FileProvider на
`cache/share`, файлы старше суток удаляются). Paramnezia открывает такие файлы (`ACTION_VIEW`/`ACTION_SEND`,
`application/octet-stream`, `text/plain`), импортирует и сразу подключается. `KeyText.extract` находит ключ
внутри текста сообщения и склеивает ключ, разорванный переносами строк. Людей можно создавать списком
(`Links.createMany`): ошибка на одном имени не мешает остальным.

Сервер: отдельный контейнер `paramnezia-invite` на `busybox httpd` (read-only, без capabilities, uid 65534,
32 МБ), порт 80 или случайный свободный; остановленный контейнер запускается снова на том же порту. Токен
передаётся во фрагменте `#…`, поэтому не попадает в превью мессенджеров, логи и Referer. Первое получение ключа
атомарно (`mv`) переносит приглашение в «использованные» и запоминает адрес: повтор разрешён только с него и
30 минут (время на установку приложения). Ссылка открывается по HTTP: она одноразовая, но содержимое по пути не
шифруется.

## Надёжность

- **Хранилище** (`data/Vault.kt`): запись во временный файл, `fsync`, атомарное переименование; предыдущее
  исправное состояние хранится как `state.bak`. Если основной файл не читается, берётся копия; если не читается
  ничего или состояние не разбирается этой версией, файлы откладываются в сторону (`*.unreadable-<время>`), а не
  перезаписываются. Ошибка записи не роняет приложение: состояние остаётся в памяти и запишется следующим
  изменением.
- **Старт VPN** при неудаче (нет сети после загрузки, DNS адреса сервера, ошибка в Go) повторяется с паузами
  10 с, 20 с, … до 15 минут, до 8 раз. Без разрешения VPN не повторяется: тут поможет только пользователь.
- **Виджет** включает VPN через невидимую activity, а не через broadcast: Android 8+ может запретить старт
  сервиса из фонового приёмника.
- **SSH**: каждое подключение пробует физическую сеть, потом туннель, и так дважды. Неверный пароль и смена
  ключа хоста не повторяются.
- **Самовосстановление флота** (`FleetManager.heal`, раз в сутки и после обновления, только на админ-устройстве):
  все устройства манифеста зарегистрированы на каждом сервере с их адресами; отключённые удалены (список
  `revoked` хранится, пока все серверы не подтвердят удаление); манифест лежит на сервере, а внутритуннельный
  httpd отвечает (запускается и в контейнерах, поставленных AmneziaVPN, и после перезагрузки VPS); сервер держит
  текущий релиз. Каждый сервер и шаг независимы, неудачи повторяются при следующем запуске.
- **Добавление устройства** требует успеха на основном сервере; резервный, лежащий в этот момент, получит
  устройство при самовосстановлении.

## Интерфейс

Тема бренда (`ui/Theme.kt`) одинакова на всех телефонах: тёмно-синий фон, фиолетовый, индиго, циан и мятный
акценты. Кнопка включения (`ui/PowerButton.kt`) целиком рисуется на Canvas: градиентный диск, ореол, «комета»
при подключении, пружинное нажатие и тактильный отклик; бесконечные анимации существуют только пока видны.
Главный экран показывает скорость, пинг сторожа, число переподключений, заблокированные трекеры и блок «Как вас
видят сайты»: адрес для зарубежных сайтов (запрос к ifconfig.co идёт через туннель) и для российских (запрос к
`ipv4-internet.yandex.net` идёт напрямую по тем же правилам, что и весь трафик). Виджет 1×1: круглая кнопка
цвета состояния и трафик под ней.

## Планы

- Регистрация в программе проверки разработчиков Android (установка не из Play), см. [PLAY-PROTECT.md](PLAY-PROTECT.md).
- HTTPS для страницы приглашений: сертификат Let's Encrypt на IP (короткоживущие IP-сертификаты) или на домен.
- Покупка VPS через API хостера для полностью автоматической замены заблокированного сервера.
- XRay/VLESS как второй протокол (заметно увеличит APK).
