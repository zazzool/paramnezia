# Google Play Protect: почему приложение помечалось и правила, чтобы этого не было

Paramnezia ставится не из Google Play, поэтому каждую установку проверяет Play Protect: на телефоне
(эвристики и модель по признакам APK) и в облаке Google (репутация файла, сертификата подписи и адреса, откуда
файл скачан). В его коде нет ничего вредоносного, но до версии 1.1.0 в приложении и вокруг него было несколько
вещей, которые в точности совпадают с признаками вредоносных программ. Этот документ перечисляет их, объясняет,
что сделано, и задаёт правила для дальнейшей разработки. CI проверяет их на каждой сборке
(`.github/scripts/apk-audit.sh`).

## Что было и что сделано

| Признак до 1.1.0 | Как это выглядит для Play Protect | Что теперь |
|---|---|---|
| Ссылка-приглашение отдавала **свой APK каждому человеку**: сервер вписывал приглашение в APK Signing Block, у каждого скачивания был новый SHA-256 | серверный полиморфизм: так распространяют трояны, чтобы каждая копия была «новой» и не имела репутации | APK одинаковый для всех, байт в байт как его подписал apksigner. Приглашение открывается в уже установленном приложении (второй шаг на той же странице) |
| Страница **сама начинала скачивание** APK через 0,4 с | drive-by download | Скачивание только по нажатию |
| APK отдавался **по HTTP с голого IP** | так раздают вредоносные APK; у такого адреса нет репутации | Основная ссылка — GitHub Releases (с 2.1.0; до этого Blossom). Копия на вашем сервере — запасной вариант, и сервер скачивает её сам, сверяя SHA-256 |
| Приложение **читало свой APK и загружало его на серверы** (шаблон для ссылок, зеркало обновлений) | самораспространение (червь) | Приложение никогда не читает, не меняет и не передаёт свой APK. Серверы сами скачивают тот же публичный релиз |
| **Тихая самоустановка** скачанных из сети APK (`UPDATE_PACKAGES_WITHOUT_USER_ACTION`, `USER_ACTION_NOT_REQUIRED`) | dropper / hostile downloader | В 1.1–2.0 ставилось по нажатию с подтверждением; с 2.1.0 приложение вообще не скачивает и не ставит APK (см. ниже) |
| В release APK лежала **лишняя пара `pnz1` в APK Signing Block** | APK изменён после подписи | Блок подписи содержит только записи подписанта (CI падает, если появится что-то ещё) |
| `QUERY_ALL_PACKAGES` (убрано в 1.0.1) | сбор списка приложений | `<queries>` только для приложений с иконкой на рабочем столе |
| `RECEIVE_BOOT_COMPLETED` в манифесте приложения | автозапуск | Убрано из нашего манифеста (оставляет только WorkManager для своих задач) |

## 2.1.0: вердикт по поведению кода

2.0.0 с новым пакетом и сертификатом всё равно получила «Вредоносное приложение заблокировано» (с «Все равно
установить»). Это вердикт анализа кода, а не репутации: модель Google сравнивает поведение, а не имена. В коде
было сочетание, типичное для вредоносных программ:

| Признак до 2.1.0 | На что похоже | Что теперь |
|---|---|---|
| Приложение **само скачивало APK** из сети (Blossom, серверы, другие устройства) и передавало его в `PackageInstaller`, держало `REQUEST_INSTALL_PACKAGES` и приёмник `MY_PACKAGE_REPLACED` | загрузчик (dropper) | Только проверка `release.json` по одному HTTPS-адресу; «Скачать» открывает браузер. Разрешения, установщика и приёмников нет |
| **Команды и настройки через Nostr-релеи** (WebSocket, свои ключи, публикация от имени каждого устройства) | управление ботнетом (C2) | Nostr удалён целиком |
| **UDP-обмен между устройствами** внутри туннеля, пересылка манифестов и релизов дальше | P2P-ботнет, самораспространение | Удалён. Устройство само читает манифест по HTTP(S), как подписку VPN |
| **Фоновое управление серверами по SSH** раз в сутки из WorkManager (`sudo`, `docker`) | удалённое управление из фона | Только когда админ открыл приложение. Фоновая задача лишь читает манифест |

## Правила (нельзя нарушать)

1. **Один APK для всех.** Никогда не менять APK после подписи и не выдавать разным людям разные файлы.
   Настройки передаются ключом `vpn://` или ссылкой, не внутри APK.
2. **Приложение не трогает APK-файлы.** Не менять, не копировать и не загружать свой APK куда-либо, не ставить
   другие пакеты. Единственное исключение — «Раздать по Wi-Fi» (2.12.0, [LAN-SHARE.md](LAN-SHARE.md)): пока человек
   держит этот экран открытым, установленный APK (тот же подписанный файл для всех) читается из
   `applicationInfo.sourceDir` и отдаётся соседу по локальной сети, только когда тот сам открыл адрес и нажал
   «Скачать». Никакой отправки на серверы, никакой раздачи в фоне.
3. **Приложение не скачивает и не ставит APK.** Ни `REQUEST_INSTALL_PACKAGES`, ни `PackageInstaller`, ни
   приёмника `MY_PACKAGE_REPLACED`. Обновление: ссылка в браузере.
4. **Скачивание только по действию человека.** Страницы не запускают загрузку сами.
5. **APK по HTTPS.** Первым всегда идёт HTTPS-адрес; HTTP с IP — только запасной путь.
6. **Минимум разрешений.** Список разрешённых — в `apk-audit.sh`. Новое разрешение — только с объяснением здесь.
   Никогда: `QUERY_ALL_PACKAGES`, специальные возможности, администратор устройства, SMS, звонки, контакты,
   наложение поверх окон, доступ к уведомлениям, геолокация, микрофон.
7. **Никакого загружаемого кода.** Ни `DexClassLoader`, ни `.dex/.jar/.apk` в assets, ни скачиваемых плагинов.
8. **Без обфускации ради скрытия.** R8 сжимает код, но строки, скрипты для сервера и логика остаются читаемыми.
9. **Не debuggable, targetSdk ≥ 35, подпись v2+ одним ключом.**
10. **Никаких P2P- и релейных сетей.** Ни Nostr, ни WebSocket-релеев, ни фонового обмена между устройствами.
    Конфигурация и обновления — только HTTP(S)-запросы к серверам семьи, зеркалам манифеста и GitHub Releases.
    «Раздать по Wi-Fi» сюда не относится: она открывается человеком, видна на экране, закрывается вместе с ним,
    ничего не пересылает дальше и выдаёт настройки только по нажатию «Разрешить» владельцем.
11. **Никаких SSH-команд из фона.** Управление серверами — только при открытом приложении или по нажатию.
    То же для API хостеров (покупка VPS, 2.2.0): запросы только по нажатию админа при открытом приложении.

## Доставка настроек: что рассматривали

Цель: ведомые устройства узнают о новых серверах и настройках, даже если все старые серверы заблокированы, и
при этом приложение не похоже на вредоносное. Решение 2.2.0: обычные HTTPS-запросы к своим серверам и к
секретному gist на GitHub, плюс Orbot, если он есть. Варианты, от которых отказались:

| Вариант | Почему нет |
|---|---|
| Nostr, P2P, обмен между устройствами | был в 1.x–2.0; именно это Play Protect принял за управление ботнетом |
| Блокчейн (данные в транзакциях или смарт-контракте) | читать всё равно через HTTPS-шлюзы (то же зеркало, только дороже); запись требует кошелька и денег; «команды из смарт-контракта» — известный приём вредоносов (EtherHiding), криптокошелёк в коде — отдельный признак |
| Встроенный Tor (tor-android, Arti) | +15–25 МБ к APK; в России без мостов не работает; конфиг с `.onion` — типичный признак C2. Вместо этого используем Orbot пользователя, если он установлен |
| Фоновый обмен по локальной сети (mDNS) | обмен между устройствами, правило 10. Ручная раздача по Wi-Fi с экраном и подтверждением добавлена в 2.12.0 ([LAN-SHARE.md](LAN-SHARE.md)) |

Правило 10 дополняется: **Tor только через установленный пользователем Orbot**, без своих Tor-библиотек.

Раздача ссылок и файлов настроек (2.2.0) идёт только через системное меню «Поделиться» по нажатию админа. Файл
содержит только ключ `vpn://` (текст), никогда APK.

## Что ещё зависит не от кода

- **Репутация.** У нового сертификата подписи и нового пакета её нет. Она копится с установками. В версии 2.0.0
  (1.11.2026) личность приложения создана заново: пакет `io.paramnezia` → `net.paramnezia`, новый сертификат
  подписи, новые ключи OTA, все классы в новом пространстве имён. Так сборки 2.x не связаны с вердиктом Play
  Protect по 1.x. Дальше сертификат и `applicationId` (`net.paramnezia`) не менять: каждая смена обнуляет
  репутацию и требует переустановки на всех устройствах.
- **Апелляция.** Если Play Protect всё равно предупреждает, подайте форму
  <https://support.google.com/googleplay/android-developer/contact/protectappeals> (текст в файле
  `play-protect-appeal.md` проекта). Предупреждение для конкретного файла снимается проверкой в облаке, поэтому
  важно, что APK теперь у всех одинаковый.
- **Отправка на проверку.** Если при установке Play Protect предлагает «Отправить приложение на проверку»,
  соглашайтесь.
- **Регистрация разработчика Android.** Google вводит обязательную проверку разработчиков приложений, которые
  ставятся не из Play (с сентября 2026 года в первых странах, дальше везде). Зарегистрируйте пакет и сертификат
  в Android Developer Console, когда это станет доступно для вашего аккаунта: это лучший способ, чтобы
  установку никогда не блокировали.
- **Xiaomi.** У MIUI/HyperOS есть своя проверка («Проверка безопасности» при установке); её предупреждения
  отдельные от Play Protect.

## Как проверить сборку руками

```sh
bash .github/scripts/apk-audit.sh paramnezia-vX.Y.Z.apk --release
```

Скрипт печатает подписи и сертификат, записи APK Signing Block, разрешения, targetSdk и состав кода.
