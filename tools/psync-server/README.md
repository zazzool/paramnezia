# Серверная часть семейного комплекта

Снимок действующего обработчика и шаблоны конфигурации systemd и CoreDNS. Подставьте FAMILY_ID вашей семьи и AUTHORITATIVE_IPV4 сервера DNS вместо маркеров в угловых скобках. Для восстановления потребуются отдельные резервные копии токена, текущего подписанного fleet.json, DNS-зоны и конфигурации nginx. В комплект входят только программные файлы.

## Как устроена публикация

nginx отдаёт fleet.json по HTTPS и проксирует PUT того же пути в writer.sock. Обработчик принимает bearer-токен из systemd LoadCredential, проверяет семейный идентификатор, структуру и версию документа. Клиенты Paramnezia проверяют криптографическую подпись. Заголовок X-Paramnezia-Endpoint обновляет A-запись в family.zone. CoreDNS перечитывает изменённую зону каждые две секунды.

## При восстановлении

1. Установите Python 3, CoreDNS с поддержкой file и nginx с действующим сертификатом psync.ru. Создайте пользователя pnmirror. Разместите writer.py, Corefile и бинарник coredns в /opt/paramnezia-mirror согласно путям в unit-файлах.
2. Восстановите токен в /opt/paramnezia-mirror/token с доступом root, исходный fleet.json в каталог BindPaths и family.zone в /var/lib/paramnezia-dns. Сохраните в зоне строку комментария « ; serial=ЧИСЛО» при записи SOA. Обработчику нужен доступ на запись в оба каталога, nginx и CoreDNS — на чтение соответствующих файлов.
3. Установите оба unit-файла в /etc/systemd/system, а dns.conf в подкаталог paramnezia-mirror.service.d. Проверьте пути и пользователя, затем перечитайте настройки systemd и запустите службы. Восстановите маршрут nginx для точного URL семьи и доступ nginx к сокету. Перед запуском проверьте конфигурацию nginx.
4. Сверьте версию fleet.json через HTTPS и IPv4 в авторитетном DNS. После публикации с телефона проверьте свежий ответ PUT 204 в журнале paramnezia-mirror и получение настроек вторым устройством. При переносе DNS проверьте доступность TCP и UDP на порту 53 и делегирование поддомена.

## Шаблоны nginx и зоны

В nginx-location.conf.in замените <FAMILY_ID> и подключите фрагмент внутри HTTPS-блока server для psync.ru. Путь /usr/share/nginx/html в контейнере nginx соответствует /root/nginx/www на хосте. Восстановите этот том либо согласуйте оба пути.

Для первого запуска заполните family.zone.in публичным IPv4 VPN вместо <VPN_IPV4> и положительным целым номером версии вместо обоих <SERIAL>. При восстановлении существующей зоны сохраните или увеличьте её serial. Для обработчика требуется первоначальный подписанный fleet.json от этой же семьи. В работающем развёртывании используется CoreDNS 1.13.1.
